# Zenith Analytics

Дашборд, который сам тянет расход из Google Ads и Meta Ads, лиды и квалы из Битрикс24 и показывает цену лида и цену квала по каналам и кампаниям. Работает бесплатно: данные раз в час собирает GitHub Actions, страницу отдаёт GitHub Pages.

Никаких выгрузок и Excel. Всё идёт из кабинетов через API.

## Как это устроено

1. Раз в час GitHub Actions запускает скрипты.
2. `fetch-google-ads.js` и `fetch-meta-ads.js` забирают расход, клики, показы по дням и кампаниям.
3. `fetch-bitrix.js` забирает сделки из воронок «Обработка заявок» и «Первичные продажи».
4. `build-data.js` связывает лиды с кампаниями по UTM и пишет `data/data.json`.
5. `index.html` читает этот файл и рисует таблицу.

В репозиторий попадают только суммы и количества по дням и кампаниям. Телефонов и имён там нет.

## Что понадобится заранее

Аккаунт GitHub, доступ админа в Google Ads (и менеджерский аккаунт, если он есть), в Meta Business Suite и в Битрикс24.

## Шаг 1. Репозиторий

1. На github.com нажми **New repository**. Название `zenith-analytics`, тип **Public** (бесплатные Pages работают на публичных).
2. Загрузи туда все файлы из архива: **Add file → Upload files**. Папку `.github` Проводник и Finder иногда не берут, потому что она скрытая. Если после загрузки её нет в репозитории, нажми **Add file → Create new file**, в имени напиши `.github/workflows/update-data.yml` и вставь содержимое файла из архива.
3. Нажми **Commit changes**.

## Шаг 2. Включить страницу

**Settings → Pages**. В Source выбери **Deploy from a branch**, ветка `main`, папка `/ (root)`, Save. Через минуту-две адрес появится вверху: `https://<твой-логин>.github.io/zenith-analytics/`.

## Шаг 3. Разрешить Actions писать в репозиторий

**Settings → Actions → General → Workflow permissions** → **Read and write permissions** → Save.

## Шаг 4. Битрикс24

1. В Битрикс24: **Разработчикам → Другое → Входящий вебхук**.
2. Права: **CRM (crm)**. Больше ничего не нужно.
3. Сохрани. Скопируй «Пример URL для вызова REST» без названия метода, он выглядит так: `https://zenith.bitrix24.kz/rest/1/abc123def456/`
4. В GitHub: **Settings → Secrets and variables → Actions → New repository secret**. Имя `BITRIX_WEBHOOK_URL`, значение этот адрес.

## Шаг 5. Meta Ads

1. **business.facebook.com → Настройки компании → Пользователи → Системные пользователи → Добавить**. Роль: Администратор.
2. Нажми «Назначить активы», выбери рекламный аккаунт, права «Управление кампаниями» достаточно (нужно чтобы был доступ на чтение).
3. **Создать токен**, выбери приложение (если приложения нет, создай на developers.facebook.com тип «Бизнес»), срок «Никогда», галочка **ads_read**. Скопируй токен.
4. Номер рекламного аккаунта: в Ads Manager вверху рядом с названием (цифры). 
5. Секреты в GitHub: `META_ACCESS_TOKEN` (токен) и `META_AD_ACCOUNT_ID` (например `act_1234567890`).

## Шаг 6. Google Ads (самый долгий)

Нужно пять вещей: токен разработчика, OAuth-ключи, refresh token, и два номера аккаунтов.

**6.1 Токен разработчика.** Открой менеджерский аккаунт Google Ads (MCC). Если его нет, создай бесплатно на ads.google.com/home/tools/manager-accounts, и привяжи к нему рекламный аккаунт Zenith. Дальше **Инструменты → Настройка → API Center**, заполни форму, получи Developer token. Нужен уровень доступа **Basic**, одобрение иногда идёт несколько дней. Пока токен в статусе «Test», он работает только с тестовыми аккаунтами, так что дождись Basic.

**6.2 Google Cloud.** На console.cloud.google.com создай проект. Дальше:
- **APIs & Services → Library**, найди **Google Ads API**, нажми Enable.
- **OAuth consent screen** (или «Audience»): тип External, заполни название и почту. Потом нажми **Publish app**, чтобы статус стал **In production**. Это важно: в режиме Testing Google сбрасывает ключ каждые 7 дней, и данные внезапно перестанут обновляться.
- **Credentials → Create credentials → OAuth client ID**, тип Web application, в Authorized redirect URIs добавь `https://developers.google.com/oauthplayground`. Сохрани Client ID и Client secret.

**6.3 Refresh token.**
1. Открой developers.google.com/oauthplayground.
2. Шестерёнка справа вверху → поставь галочку **Use your own OAuth credentials**, вставь Client ID и Secret.
3. В списке слева вручную впиши `https://www.googleapis.com/auth/adwords`, нажми Authorize APIs, войди под почтой, у которой есть доступ к рекламному аккаунту. Если Google пишет «приложение не проверено», нажми «Дополнительно → Перейти».
4. Нажми **Exchange authorization code for tokens**, скопируй **Refresh token**.

**6.4 Номера аккаунтов** (без дефисов):
- `GOOGLE_ADS_CUSTOMER_ID`: номер рекламного аккаунта Zenith (xxx-xxx-xxxx в углу Google Ads).
- `GOOGLE_ADS_LOGIN_CUSTOMER_ID`: номер менеджерского аккаунта (MCC). Если заходишь без MCC, оставь пустым.

**6.5 Секреты в GitHub:** `GOOGLE_ADS_DEVELOPER_TOKEN`, `GOOGLE_ADS_CLIENT_ID`, `GOOGLE_ADS_CLIENT_SECRET`, `GOOGLE_ADS_REFRESH_TOKEN`, `GOOGLE_ADS_CUSTOMER_ID`, `GOOGLE_ADS_LOGIN_CUSTOMER_ID`.

Если Google ещё не одобрил токен, можно запустить проект без него: Meta и Битрикс отработают, а Google добавишь позже. Для этого временно убери `npm run fetch:google &&` из `package.json` в строке `update`.

## Шаг 7. Первый запуск

**Actions → Update data → Run workflow**. Через пару минут рядом появится зелёная галочка. Если красный крестик, открой запуск и посмотри, на каком шаге упало. Текст ошибки пишет по-русски, что поправить (например, не найдена воронка или протух токен).

Открой адрес из шага 2. Должна быть таблица. Внизу блок «Диагностика»: там видно, какие метки не распознаны и сколько оплат нашлось.

## Шаг 8. UTM-метки (главное для точности)

Связка лидов с кампаниями работает по **id кампании в utm_campaign**. Это надёжнее любых названий: кампанию можно переименовать, связь не сломается.

**Google Ads.** Один раз на уровне аккаунта: **Настройки аккаунта → Отслеживание → Шаблон отслеживания**:

```
{lpurl}?utm_source=google&utm_medium=cpc&utm_campaign={campaignid}&utm_content={adgroupid}&utm_term={keyword}
```

Не забудь убрать старые UTM из конечных ссылок объявлений и из шаблонов на уровне кампаний, иначе они перебьют аккаунтный шаблон. Для Performance Max `{keyword}` будет пустым, это нормально.

**Meta.** В каждом объявлении, поле «Параметры URL»:

```
utm_source=meta&utm_medium=paid&utm_campaign={{campaign.id}}&utm_content={{ad.id}}&utm_term={{adset.id}}
```

Чтобы не делать это вручную в каждом объявлении, в Ads Manager можно выделить все объявления и массово поправить поле.

**Яндекс и Сату.** `utm_source=yandex` и `utm_source=satu`. API у них нет, поэтому расход вносится руками (ниже). Название кампании в метке для них не важно: считается общий итог по каналу.

**На сайте.** Убедись, что формы передают UTM в сделку Битрикса в поля `UTM_SOURCE`, `UTM_MEDIUM`, `UTM_CAMPAIGN`, `UTM_CONTENT`, `UTM_TERM`. Это у вас уже работает.

## Шаг 9. Названия кампаний

Дашборд берёт название кампании прямо из кабинета, поэтому подойдёт любое. Для порядка удобно называть так:

```
Направление | Тип | Уточнение
ЛКМ | Лендинг | Квиз
Наполь | Сайт | Поиск
Огнез | Perf Max
```

Если хочешь, чтобы несколько кампаний слились в одну строку, правила группировки лежат в `config/campaign-map.json`. Не подошло ни одно правило, кампания показывается под своим названием.

## Настройки: `config/settings.json`

- `usdToKzt` — курс по месяцам. Кабинеты отдают доллары, дашборд считает в тенге по этим курсам. Добавляй новый месяц, например `"2026-10": 520`. Для месяцев без записи берётся `default`.
- `manualSpendKzt` — расход Сату и Яндекса по месяцам, в тенге. Размазывается равномерно по дням месяца.
- `stages` — точные названия этапов в Битриксе. Если квалы или оплаты не считаются, сверь с блоком «Диагностика», там список этапов из CRM.
- `funnels` — названия воронок.
- `excludeCampaignKeywords` — слова в названии кампании, которые надо исключить из расчёта.

## Как читать цифры

- Лид: сделка в «Обработке заявок» без этапов СПАМ и ДУБЛЬ.
- Квал: этап «КВАЛИФИКАЦИЯ ПРОЙДЕНА».
- Лиды и квалы стоят на дате создания лида. Оплаты и выручка на дате оплаты. Поэтому ROAS за короткий период шумит.
- Оплата привязывается к каналу через контакт: ищется первый лид этого клиента с известной меткой. Если не нашёлся, берётся метка самой сделки продаж, иначе «Без метки».
- Звонки и часть WhatsApp приходят без UTM. Они лежат в строке «Без метки», расход на них не делится.

## Если что-то не работает

| Что видишь | Что делать |
|---|---|
| `invalid_grant` в логе Google | Refresh token протух. Проверь, что consent screen в статусе In production, получи токен заново |
| `DEVELOPER_TOKEN_NOT_APPROVED` | Google ещё не дал уровень Basic |
| `Не нашёл воронки в Битрикс` | Скопируй точное название из сообщения в `config/settings.json` |
| Meta: `OAuthException` | Токен без права ads_read или аккаунт не назначен системному пользователю |
| Квалов 0 | Названия этапов в `settings.json` не совпали с CRM |
| Много «метка не распознана» | Метки ещё старые. После шага 8 новые лиды будут связываться сами |
| Workflow не запускается по расписанию | GitHub отключает расписание в репозитории без активности 60 дней. Нажми Run workflow вручную |

## Безопасность

Токены лежат только в GitHub Secrets, в коде их нет. Репозиторий публичный, поэтому в нём и на странице видны суммы расхода и количество лидов по кампаниям. Если это нежелательно, нужен платный GitHub для приватных Pages, либо можно выложить `index.html` и `data/data.json` на Netlify с паролем.
